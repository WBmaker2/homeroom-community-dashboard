# 담임 하루 운영 대시보드 설계

## 개요

이 문서는 초중등 담임교사를 위한 웹앱 **오늘 우리 반**의 첫 버전 설계이다. 앱의 목적은 선생님이 매일 아침이나 방과 후에 학급 상태를 빠르게 파악하고, 자리 배치, 칭찬 기록, 학급 회의 안건, 학급 규칙을 하나의 흐름으로 운영하도록 돕는 것이다.

첫 버전은 **교사 중심 + 일부 학생 참여형**으로 설계한다. 교사는 모든 운영 기록을 관리하고, 학생은 안건 제출, 규칙 의견/투표, 칭찬 제보처럼 제한된 참여 기능만 사용한다. 학생에게는 교사용 민감 기록, 자리 배치 조건, 관계 메모, 개별 학생 기록을 노출하지 않는다.

## 목표

- 담임교사가 하루 5분 안에 오늘 확인해야 할 학급 운영 신호를 볼 수 있게 한다.
- 자리 배치, 칭찬 기록, 회의 안건, 규칙 합의 기능을 한 대시보드에서 연결한다.
- 학생 참여는 학급 자치와 긍정 문화 형성에 필요한 범위로 제한한다.
- 학생 정보는 최소한으로 다루고, 민감 정보는 교사 전용으로 분리한다.

## 대상 사용자

- 주 사용자: 초등학교, 중학교, 고등학교 담임교사
- 보조 사용자: 담임이 참여 링크나 코드를 열어준 학급 학생

초중등 공통 도구로 시작하되, 문구와 기본 예시는 초등 고학년부터 중학교까지 자연스럽게 사용할 수 있는 톤으로 둔다. 고등학교에서도 사용할 수 있도록 기능 이름은 특정 학교급에 묶지 않는다.

## 접근 권한과 학급 범위

첫 버전은 **교사 계정 기반**으로 설계한다. 한 교사 계정은 여러 학급을 만들 수 있고, 모든 데이터는 `classId` 단위로 분리한다. 대시보드, 학생 명부, 자리 배치, 칭찬 기록, 안건, 규칙, 학생 참여 활동은 모두 특정 학급에 속한다.

첫 버전에서는 공동 담임, 학년부 공유, 관리자 계정, 학급 소유권 이전 기능을 제공하지 않는다. 교사가 학급을 더 이상 운영하지 않는 경우에는 학급을 보관 상태로 바꿔 읽기 전용으로 유지하거나, 명시적 확인 후 삭제한다. 이 결정은 권한 모델을 단순하게 유지하고 학생 데이터가 다른 학급이나 다른 교사에게 섞이는 일을 막기 위한 것이다.

학생은 영구 계정을 만들지 않는다. 학생 참여는 교사가 학급별로 여는 **참여 활동**을 통해서만 가능하다. 참여 활동은 `activityId`, 활동 유형, 공개 기간, 익명 여부, 중복 제출 정책, 참여 코드, 상태를 가진다.

## 첫 버전 범위

첫 버전에 포함할 기능은 다섯 가지이다.

1. **오늘 우리 반 대시보드**
   - 새 회의 안건, 진행 중인 투표, 칭찬 공백, 자리 배치 주의사항, 점검할 학급 약속을 보여준다.
   - 빠른 기록 버튼으로 칭찬 기록, 안건 정리, 규칙 제안, 자리 조건 수정에 진입한다.

2. **자리 배치 시뮬레이터**
   - 학생 명부와 교실 좌석표를 바탕으로 자리 배치 추천안을 만든다.
   - 조건은 `앞자리 권장`, `분리 필요`, `도움 짝 권장`, `시야 배려`, `집중 지원`처럼 중립적인 운영 용어로 다룬다.
   - 추천 결과는 교사가 직접 수정할 수 있으며, 시스템은 추천안이 정답이라고 표현하지 않는다.

3. **칭찬·격려 기록장**
   - 학생별 좋은 행동을 날짜, 태그, 짧은 메모로 기록한다.
   - 최근 칭찬 기록이 적은 학생을 대시보드에서 알려준다.
   - 주간 칭찬 요약과 격려 문구 초안을 생성한다. 첫 버전의 문구 생성은 기록 기반 템플릿과 규칙형 추천으로 시작한다.

4. **학급 회의 안건함**
   - 학생은 참여 화면에서 안건을 제출한다.
   - 교사는 안건을 `검토 대기`, `채택`, `보류`, `병합됨`, `종료` 상태로 관리한다.
   - 교사는 학생 표현을 회의용 문장으로 다듬고 공개 여부를 결정한다.

5. **규칙 합의판**
   - 회의에서 나온 내용을 규칙 후보로 만들 수 있다.
   - 학생은 교사가 연 투표에 참여한다.
   - 투표가 끝나면 교사가 최종 확정한 규칙을 학급 약속으로 저장하고, 점검 날짜를 설정한다.

## 첫 버전 제외 범위

다음 기능은 첫 버전에서 제외한다.

- 생활지도 사건 기록
- 상담 기록
- 보호자 연락 기록
- NEIS 연동
- 실명 계정 기반 학생 로그인
- AI가 학생 상태나 행동을 자동 판단하는 기능
- 학생 간 관계를 학생에게 보여주는 관계망 기능
- 학교 관리자용 통계 화면

이 제외 범위는 앱의 성격을 긍정적 학급 운영 도구로 유지하고, 개인정보 위험과 구현 범위를 줄이기 위한 결정이다.

## 화면 구조

### 교사용 화면

교사용 첫 화면은 **오늘 우리 반** 대시보드이다.

상단에는 오늘 확인할 신호를 보여준다.

- 새로 제출된 회의 안건
- 진행 중이거나 마감이 가까운 규칙 투표
- 일정 기간 칭찬 기록이 없는 학생
- 자리 배치 추천에서 충돌한 조건
- 점검일이 가까운 학급 약속

옆에는 빠른 기록 영역을 둔다.

- 칭찬 기록 추가
- 회의 안건 정리
- 규칙 후보 만들기
- 자리 배치 조건 수정

하단에는 네 기능 카드가 있다.

- 자리 배치
- 칭찬 기록
- 회의 안건
- 규칙 합의

각 기능은 독립적으로 사용할 수 있지만, 대시보드에서는 필요한 신호만 요약해 보여준다.

### 학생 참여 화면

학생 화면은 교사용 화면과 분리한다. 학생은 교사가 공유한 참여 링크와 참여 코드로 접근한다. 첫 버전에서는 학생별 영구 계정을 만들지 않는다.

학생이 할 수 있는 일은 다음 네 가지로 제한한다.

- 회의 안건 제출
- 규칙 후보에 대한 의견 작성
- 규칙 투표 참여
- 칭찬 제보

학생 화면에는 다른 학생의 개별 기록, 교사용 메모, 자리 조건, 관계 조건, 칭찬 공백 정보가 보이지 않는다. 익명 여부는 기능별로 교사가 설정한다.

학생 참여 식별은 다음 규칙을 따른다.

- 교사가 활동을 열면 참여 링크와 참여 코드가 만들어진다.
- 학생은 참여 화면에서 참여 코드와 학급 번호를 입력한다.
- 학급 번호는 학생 명부에 있는 번호만 허용한다. 앞뒤 공백을 제거하고 숫자 문자열로 정규화한 뒤 학생 명부의 `studentNumber`와 비교한다.
- 시스템 내부에서는 모든 학생 기록을 `studentId`로 연결한다. 학생이 입력한 학급 번호는 `studentId`를 찾기 위한 참여 화면 입력값으로만 사용한다.
- 투표처럼 1인 1회가 필요한 활동은 `classId + activityId + studentId` 조합으로 중복을 막는다.
- 같은 학생 번호로 이미 제출된 투표가 있으면 새 투표를 저장하지 않고, 이미 참여했다는 안내를 보여준다.
- 교사는 학생이 번호를 잘못 입력한 경우를 처리하기 위해 특정 활동의 특정 번호 제출 기록을 삭제하고 다시 참여하게 할 수 있다.
- 익명 활동에서도 중복 방지 키는 저장하지만, 교사용 화면에는 제출자 이름이나 번호를 표시하지 않는다.
- 활동에는 시작 상태와 종료 상태가 있으며, 종료된 활동은 새 제출을 받지 않는다.
- 안건 제출과 칭찬 제보는 기본적으로 여러 번 제출할 수 있고, 투표는 기본적으로 1회만 제출할 수 있다.

## 모듈 구조

앱은 다섯 개의 주요 모듈로 나눈다.

### 1. 학생 명부 모듈

학생 명부는 `studentId`, `studentNumber`, 이름, 표시명, 기본 배려 정보를 관리한다. `studentId`는 시스템이 생성하는 내부 식별자이고, `studentNumber`는 학급 안에서 교사가 관리하는 번호이다. 다른 모듈은 학생을 `studentId`로 참조한다. 학생 화면에는 필요한 표시명과 활동 입력에 필요한 학급 번호만 사용한다.

### 2. 대시보드 신호 모듈

각 기능에서 생성된 기록을 직접 모두 보여주지 않고, 오늘 확인할 신호로 요약한다. 이 모듈은 새 안건 수, 칭찬 공백, 자리 조건 충돌, 투표 마감, 약속 점검일을 계산한다.

### 3. 자리 배치 모듈

교실 좌석표, 학생 명부, 자리 조건을 입력받아 추천 배치안을 만든다. 좌석표는 행과 열 기반 격자로 시작한다. 각 좌석은 `seatId`, 행, 열, 사용 가능 여부, 고정 배정 여부를 가진다. 교사는 사용하지 않는 좌석을 비활성화할 수 있고, 특정 학생의 자리를 고정할 수 있다.

자리 조건은 강한 조건과 약한 조건으로 나눌 수 있다.

- 강한 조건: 분리 필요, 시야 배려, 앞자리 권장
- 약한 조건: 도움 짝 권장, 집중 지원, 최근 칭찬 공백 학생 배려

`앞자리 권장`은 교사가 지정한 앞쪽 행 범위에 앉히는 조건이다. `시야 배려`도 첫 버전에서는 같은 방식으로 계산하며, 별도의 장애물이나 시야 가림 모델은 만들지 않는다. `분리 필요`은 지정한 두 학생이 상하좌우 인접 좌석에 배치되지 않도록 하는 강한 조건이다. `도움 짝 권장`은 지정한 두 학생을 맨해튼 거리 2 이하의 가까운 좌석에 두는 약한 조건이다. 첫 버전에서는 별도 모둠 데이터나 조별 활동 배치 기준을 두지 않는다.

추천 배치안에는 충족한 조건과 충돌한 조건을 함께 보여준다. 강한 조건을 모두 만족할 수 없으면 추천을 중단하지 않고, 충돌한 조건과 가장 덜 충돌하는 배치안을 함께 보여준다. 교사는 드래그 또는 선택 방식으로 결과를 수정할 수 있다.

좌석표와 조건의 최소 스키마는 다음과 같다.

```json
{
  "seatMap": {
    "rows": 5,
    "columns": 6,
    "disabledSeatIds": ["r5c6"],
    "fixedAssignments": [
      { "studentId": "s03", "seatId": "r1c2" }
    ]
  },
  "constraints": [
    { "type": "frontPreferred", "studentId": "s01", "frontRows": 2, "strength": "hard" },
    { "type": "visibilityPreferred", "studentId": "s02", "frontRows": 2, "strength": "hard" },
    { "type": "separateAdjacent", "studentIds": ["s04", "s12"], "strength": "hard" },
    { "type": "supportPair", "studentIds": ["s07", "s18"], "maxDistance": 2, "strength": "soft" }
  ]
}
```

### 4. 칭찬 기록 모듈

칭찬 기록은 학생, 날짜, 태그, 메모, 공개 여부를 가진다. 기본값은 교사 전용 기록이다. 학생 제보 칭찬은 바로 공개하지 않고 교사 검토 대기 상태로 들어간다.

주간 요약은 학생별 좋은 행동 기록을 모아 짧은 문장 초안으로 만든다. 문구는 교사가 수정한 뒤 사용할 수 있다.

### 5. 안건·규칙 모듈

회의 안건과 규칙 합의를 하나의 흐름으로 연결한다.

1. 학생이 안건을 제출한다.
2. 교사가 안건을 검토하고 채택, 보류, 병합한다.
3. 채택된 안건을 회의 안건으로 정리한다.
4. 회의 결과를 규칙 후보로 전환할 수 있다.
5. 학생 투표 후 교사가 최종 규칙으로 확정한다.
6. 확정된 규칙은 학급 약속으로 저장되고 대시보드에 점검 신호를 만든다.

안건 상태는 하나의 enum으로 관리한다.

| 표시 상태 | 내부 상태 | 허용되는 다음 상태 |
| --- | --- | --- |
| 검토 대기 | `PENDING_REVIEW` | `SELECTED`, `DEFERRED`, `MERGED`, `CLOSED` |
| 채택 | `SELECTED` | `CLOSED` |
| 보류 | `DEFERRED` | `SELECTED`, `CLOSED` |
| 병합됨 | `MERGED` | `CLOSED` |
| 종료 | `CLOSED` | 없음 |

규칙 후보 상태는 안건 상태와 분리한다.

| 표시 상태 | 내부 상태 | 허용되는 다음 상태 |
| --- | --- | --- |
| 초안 | `DRAFT` | `COLLECTING_FEEDBACK`, `VOTING`, `DISCARDED` |
| 의견 수집 | `COLLECTING_FEEDBACK` | `VOTING`, `DISCARDED` |
| 투표 중 | `VOTING` | `VOTE_CLOSED` |
| 투표 종료 | `VOTE_CLOSED` | `CONFIRMED`, `DISCARDED` |
| 확정 | `CONFIRMED` | `ARCHIVED` |
| 폐기 | `DISCARDED` | 없음 |
| 보관 | `ARCHIVED` | 없음 |

회의 결과를 규칙 후보로 전환하는 일은 안건 상태가 아니라 별도 생성 동작이다. 확정된 규칙은 학급 약속이 되며, 점검일과 활성/보관 상태를 가진다.

## 데이터 흐름

기본 데이터 흐름은 다음과 같다.

1. 교사가 계정으로 접속한다.
2. 교사가 학급을 선택하거나 새 학급을 만든다.
3. 교사가 학생 명부를 만든다.
4. 교사는 칭찬 기록, 자리 조건, 회의 안건, 규칙 후보를 관리한다.
5. 교사가 학생 참여 활동을 열면 참여 링크와 코드가 만들어진다.
6. 학생은 참여 화면에서 안건, 의견, 투표, 칭찬 제보를 제출한다.
7. 안건, 규칙 의견, 칭찬 제보는 교사 검토 대기 상태로 저장된다.
8. 투표 응답은 중복 검사를 통과하면 즉시 해당 규칙 후보의 투표 집계에 반영된다.
9. 교사가 채택하거나 확정한 항목만 학급 운영 흐름에 반영된다.
10. 대시보드는 각 모듈에서 오늘 볼 필요가 있는 신호만 모아 표시한다.

대시보드 시간 기준은 첫 버전에서 고정한다. `오늘`은 교사 기기 또는 서버의 지역 날짜 기준 당일이다. `최근 칭찬 공백`은 기본 7일 동안 칭찬 기록이 없는 학생을 뜻한다. `마감이 가까운 투표`는 종료까지 24시간 이하인 투표를 뜻한다. `주간 요약`은 월요일부터 일요일까지의 기록을 기본 주간 범위로 사용한다.

## 민감 정보 처리

민감 정보는 처음부터 교사 전용으로 분리한다.

- 자리 조건은 학생 화면에 노출하지 않는다.
- 관계나 갈등 관련 조건은 `분리 필요`처럼 운영상 필요한 중립 표현으로 저장한다.
- 부정적 생활지도 기록장은 첫 버전에 넣지 않는다.
- 칭찬 기록은 긍정 기록을 중심으로 하며, 학생 제보는 교사 검토 후에만 활용한다.
- 규칙 의견과 회의 안건은 교사가 공개 여부를 결정한다.

앱은 학생을 평가하거나 낙인찍는 표현을 피한다. 추천과 요약은 교사 판단을 돕는 보조 정보로만 표시한다.

## 오류와 예외 처리

첫 버전에서 반드시 다룰 오류 상황은 다음과 같다.

- 학생 명부가 비어 있으면 대시보드 대신 명부 추가 안내를 보여준다.
- 자리 조건이 충돌하면 추천 실패로 끝내지 않고, 충돌 이유와 수정 가능한 조건을 보여준다.
- 학생 참여 링크가 닫혀 있으면 제출 화면 대신 참여 종료 안내를 보여준다.
- 중복 투표가 감지되면 새 투표를 저장하지 않고 학생에게 이미 참여했다는 안내를 보여준다.
- 부적절한 안건이나 칭찬 제보는 공개되지 않고 교사 검토 대기 상태에 머문다. 교사는 이를 보류, 삭제, 표현 수정 후 채택 중 하나로 처리할 수 있다.
- 주간 칭찬 문구를 만들 기록이 부족하면 억지 문구를 만들지 않고 기록 추가를 안내한다.
- 교사가 학급을 보관 상태로 바꾸면 학생 참여 링크는 자동으로 닫히고 교사용 화면은 읽기 전용으로 전환된다.

## 검증 기준

구현 후 다음 흐름이 실제로 동작해야 한다.

1. **자리 배치 흐름**
   - 학생 명부를 만든다.
   - 행과 열 기반 좌석표를 만든다.
   - 사용하지 않는 좌석이나 고정 좌석을 설정한다.
   - 자리 조건을 입력한다.
   - 추천 좌석표를 생성한다.
   - 충돌 조건을 확인한다.
   - 교사가 직접 좌석을 수정한다.

2. **칭찬 기록 흐름**
   - 교사가 학생별 칭찬 기록을 추가한다.
   - 대시보드에서 칭찬 공백 학생을 확인한다.
   - 주간 칭찬 요약과 격려 문구 초안을 확인한다.
   - 교사가 문구를 수정할 수 있다.

3. **안건·규칙 흐름**
   - 교사가 학생 참여 활동을 연다.
   - 학생이 안건을 제출한다.
   - 교사가 안건을 채택한다.
   - 회의 결과를 규칙 후보로 만든다.
   - 학생이 투표한다.
   - 교사가 규칙을 확정한다.
   - 대시보드에 점검할 학급 약속이 표시된다.

4. **학생 정보 보호 흐름**
   - 학생 화면에서 교사용 민감 기록이 보이지 않는다.
   - 학생 제보와 안건은 교사 검토 전 공개되지 않는다.
   - 익명으로 설정한 참여 항목은 학생 화면에 제출자 정보를 표시하지 않는다.
   - 익명 투표에서도 같은 참여자가 중복 투표를 할 수 없다.

## 성공 기준

- 담임교사가 대시보드만 보고 오늘 확인할 학급 운영 항목을 이해할 수 있다.
- 자리 배치 추천이 교사의 조건을 설명 가능한 방식으로 반영한다.
- 칭찬 기록이 학생별 긍정 피드백 공백을 줄이는 데 도움을 준다.
- 학생이 제출한 안건이 교사 검토를 거쳐 회의와 규칙 합의로 자연스럽게 이어진다.
- 학생 참여 화면에서 교사용 민감 정보가 노출되지 않는다.
