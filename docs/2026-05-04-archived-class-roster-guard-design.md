# 보관 학급 읽기 전용과 명부 검증 설계

## 배경

학급 보관 정책은 기존 설계에서 `보관 상태 학급은 읽기 전용으로 전환하고 학생 참여 활동은 자동 종료한다`고 정의되어 있다. 현재 구현은 학급을 보관할 때 참여 활동을 닫지만, 교사용 운영 화면의 입력 버튼과 학생 명부 수정은 계속 사용할 수 있다. 또한 학생 번호 중복 검증이 약해 학생 화면의 번호 매칭이 잘못될 수 있다.

## 목표

- 보관 학급에서는 교사용 운영 데이터가 변경되지 않게 한다.
- 보관 학급의 학생 참여는 명확한 안내와 함께 차단한다.
- 학생 등록과 수정 시 같은 학급 안에서 중복 학번을 막는다.
- 표시명이 비어 있으면 이름을 표시명으로 자동 보정한다.
- JSON 백업 다운로드/가져오기와 새 학급 등록은 보관 학급 선택 중에도 사용할 수 있게 둔다.

## 비목표

- 학급 삭제 확인 모달 추가
- CSV/붙여넣기 명부 일괄 등록
- 서버 기반 권한 관리
- 교사별 역할 권한

## 정책

### 보관 학급 읽기 전용

보관 학급은 기존 기록을 확인할 수 있지만 새 운영 기록을 만들거나 수정하지 않는다.

- 자리 배치: 추천 재생성, 좌석 수동 배치, 미사용 좌석 토글, 조건 추가 차단
- 칭찬 기록: 교사 칭찬 추가, 학생 제보 승인/보류 차단
- 회의 안건: 안건 제출 활동 열기, 교사 안건 추가, 안건 상태 변경, 회의용 문장 수정, 규칙 후보 전환 차단
- 규칙 합의: 규칙 후보 생성, 투표 열기, 후보 상태 변경, 학급 약속 확정 차단
- 학급 설정: 현재 학급의 이름/학교급/학생 명부 편집 차단. 상태 변경은 보관 해제를 위해 허용한다.

UI 비활성화만으로는 부족하므로 상태 액션도 보관 학급이면 운영 데이터 변경을 무시한다.

### 학생 참여 차단

학생 화면에서 현재 학급이 보관 상태이면 참여 코드가 맞아도 제출 버튼을 막고 `보관된 학급 활동입니다. 선생님께 새 참여 코드를 확인해 주세요.`라고 안내한다.

### 학생 명부 검증

학생 번호는 `normalizeRosterNumber`로 정규화한 뒤 비교한다.

- 등록: 정규화된 번호가 비어 있으면 실패
- 등록: 같은 학급에 같은 번호가 있으면 실패
- 수정: 자기 자신을 제외하고 같은 번호가 있으면 실패
- 표시명: 비어 있으면 이름으로 저장

## 확인 기준

- 보관 학급에서 교사용 운영 버튼이 비활성화된다.
- 보관 학급에서 상태 액션을 호출해도 운영 데이터가 바뀌지 않는다.
- 보관 학급 학생 화면은 참여를 막고 안내 문구를 보여준다.
- 같은 학급 안에서 중복 학번 등록과 수정이 차단된다.
- 기존 테스트와 빌드가 통과한다.

## 구현 기록

- 학생 번호 중복 검증을 `hasRosterNumberConflict`로 분리하고, 학생 등록/수정 액션에서 정규화된 번호 기준으로 차단한다.
- 보관 학급에서는 교사용 운영 setter와 자리 배치 상태 변경 액션을 무시하도록 상태 레벨 가드를 추가했다.
- 교사용 대시보드 헤더와 각 운영 화면에 보관 학급 안내를 표시하고, 운영 입력/버튼을 비활성화했다.
- 보관 학급에서는 학생 링크 복사와 학생 제출 버튼을 비활성화하고, 학생 화면에 종료 안내를 보여준다.
- 학생 표시명은 등록/수정 시 비어 있으면 이름으로 저장한다.
